## 1. 产品概述

### 1.1 一句话定位

一个**单人来稿、多人围观**的个人博客：志伟的唯一身份是作者与管理员；访客只能阅读和评论，**任何人（包括通过写作后台路径）都无法以网页方式修改、置顶、归类或删除志伟发布的内容**。

### 1.2 产品性质

- **不是**通用博客平台（非博客园/CSDN 模式）：没有注册作者体系、没有投稿、没有多人协作。
- **是**个人展示窗口：呈现志伟在学习与工作中的沉淀（IVD / 生物信息 / AI 思考等），配合精致克制的视觉设计。
- 视觉基准：参考 <https://gsh150801.github.io/tech-blog/> 的排版气质（纸墨质感、印章 Logo、⌘K 搜索、主题切换动画），但**不复制其内容结构与系列功能**，按本 PRD 的信息架构独立设计。

### 1.3 目标用户

| 角色     | 说明                                 | 权限                                                   |
| ------ | ---------------------------------- | ---------------------------------------------------- |
| 站长（志伟） | 唯一作者与管理员。GitHub 账号 zwl8620，PAT 持有人 | 发布、编辑、删除、置顶、归类、上传附件、管理站点配置                           |
| 访客     | 任何打开网站的人，无需注册登录                    | **仅阅读**（浏览文章/标签/合集/关于页、搜索、复制文字、RSS 订阅）+ GitHub 登录评论 |

### 1.4 核心设计原则

1. **权限最小化**：网页端所有"写"能力集中在一个需 PAT 认证的隐藏后台；访客侧零写接口。
2. **零成本**：全链路仅使用 GitHub 免费服务（Pages / Actions / Contents API）。
3. **静态优先**：访客访问的全部是预渲染 HTML，无动态服务端，攻击面极小。
4. **单人可维护**：技术栈单一（Astro + git），运营动作只有"写文章"一件事。

## 2. 权限模型（重点章节）

### 2.1 权限矩阵

| 能力               |  站长（后台+PAT） |            访客（网页）           |
| ---------------- | :---------: | :-------------------------: |
| 阅读文章 / 标签页 / 合集页 / 关于页 |      ✅      |              ✅              |
| 全文搜索（⌘K）         |      ✅      |              ✅              |
| RSS 订阅           |      ✅      |              ✅              |
| 发表/编辑/删除文章       | ✅（经 PAT 认证） |          ❌ 无入口、无接口          |
| 置顶 / 取消置顶        | ✅（经 PAT 认证） |              ❌              |
| 归类（标签/合集调整）      | ✅（经 PAT 认证） |              ❌              |
| 上传图片/附件          | ✅（经 PAT 认证） |              ❌              |
| 评论（giscus，本期）     |      ✅      | ✅（需 GitHub 登录，仅能评论，不能改他人内容） |

### 2.2 权限防线（四层）

1. **接口层**：访客-facing 页面是纯静态 HTML，不含任何写操作代码；唯一写通道是 `/console/` 后台页内的 GitHub Contents API 调用，且必须携带有效 PAT。
2. **认证层**：PAT 使用 GitHub **细粒度令牌（Fine-grained token）**——repository 限定为 `zwl8620/tech_blog` 一个仓库，权限仅勾选 `Contents: Read and write`，设置过期时间（建议 90 天，到期重发）。**没有 PAT = 一切写操作直接被 GitHub API 401 拒绝**。
3. **防枚举层**：
   - 后台采用自定义隐藏路径（如 `/console-lzw/`，**构建时**由环境变量注入，源码中不硬编码明文路径；修改路径需重新构建部署）；
   - **robots.txt 不写入后台路径**（robots 是公开文件，写 Disallow 等于向所有人广播隐藏路径）；后台路径不进 sitemap.xml 与 RSS；
   - 后台页在无有效 Token 时只显示一个"输入访问令牌"表单，不暴露任何站点管理功能与仓库信息。
4. **仓库层**：仓库归属志伟个人账号；可选开启 Branch Protection（main 分支禁止他人 force push）；GitHub 账号本身启用 2FA。

### 2.3 评论权限边界（本期，giscus）

评论基于 giscus（GitHub Discussions 驱动）：评论者需 GitHub OAuth 登录，评论数据存于仓库 Discussions（志伟拥有管理权，可删除/锁定），评论者**只能发评论**，不能触碰文章内容——与本 PRD 权限原则一致。评论属"附加内容"，不进入文章数据层，不随站点构建。

### 3.2 前台功能明细

#### F1 首页 `/`

- Hero 区：印章式 Logo（"LZW" 朱砂印章风格）+ 站名「LZW 的个人主页」+ 标语。
  - 标语（从简介基句提炼）：**「拾学习之美 · 思 AI 之变」**（候选，批准时可改）。
  - 简介段（完整版放关于页，首页放精简两句）：
    > 这里是 Lian ZhiWei 的个人博客。分享个人学习与工作中值得记录的内容，以及 AI 时代的一些思考。
- 统计块：文章数 / 标签数 / 合集数（构建时自动计算）。
- 置顶文章卡（若存在 `pinned: true` 文章，展示最新一篇；无则隐藏该区块）。
- 最新文章：最近 6 篇，条目样式 = 分离式日期块 + 标题 + 标签徽章 + 阅读时长 + 摘要。
- 合集速览：书架式横向卡片（有合集时展示，链接至 /collections/）。
- 页脚：导航重复 + GitHub 主页链接 + 邮箱（`862085716@qq.com`）+ RSS + 版权「© 2026 LZW · 用 Astro 构建」。

#### F2 文章列表页 `/posts/`

- 全部已发布文章按 `date` 倒序，分页（每页 10 篇）。
- **置顶规则**：`pinned: true` 的文章浮于列表顶部（多篇置顶时彼此仍按日期倒序），其余文章按日期倒序。
- 每条：日期块、标题、标签、阅读时长、一句话摘要（取 frontmatter `description`）。
- 顶部提供标签快捷筛选 chips。
- 日期显示全站统一 `YYYY-MM-DD` 格式。

#### F3 文章详情页 `/posts/<slug>/`

- 正文 Markdown 渲染（GFM：表格 / 任务列表 / 脚注 / 折叠块），代码块 Shiki 双主题高亮。
- 右侧 TOC 目录（滚动高亮当前章节，移动端折叠）。
- 文章头：标题、日期（YYYY-MM-DD）、标签、合集归属（若有）、阅读时长。
- 文章尾导航规则：**属于合集的文章只显示"合集导航盒"（本合集上一篇/下一篇/返回合集目录，按 seriesOrder）；不属于任何合集的文章显示全局上一篇/下一篇（按发布时间）**——两组导航不同时出现。
- **只读**：页面无任何编辑按钮暴露给访客。
- slug 规则：ASCII（英文/拼音/hash），规避 GitHub Pages 中文 URL 404 问题；**slug 一经发布不可变更**（giscus 评论按页面路径绑定，改 slug 会导致评论失联，见 F19）。

#### F4 标签页 `/tags/` + `/tags/<tag>/`

- 标签云：全部标签 + 文章计数，字号按文章数分档。
- 单标签页：该标签下全部文章列表（条目样式同 F2，**不分页**——个人博客单标签文章量小）。
- 标签 URL 同样 ASCII 化；中文标签在页面上正常显示中文（URL 层做映射）。
- **归类权限**：标签只能由站长在后台创建/调整，访客无任何归类入口。

#### F5 关于页 `/about/`

- **个人简介**（基于志伟基句润色，PRD 附终稿见 §6.1）。
- 研究与关注方向：AI 应用与思考、生信分析笔记、IVD 体外诊断研发等（依据首批文章方向拟定，批准时可增删）。
- 联系方式：📧 <862085716@qq.com>（mailto 链接）+ GitHub 链接（github.com/zwl8620）。
- 本站说明：一小段"关于这个博客"（技术栈与建站初衷）。

#### F6 全文搜索

- ⌘K / Ctrl+K 唤起模态框；Pagefind 构建时索引，懒加载，支持中文。
- **索引范围：仅文章页**（标题 + 正文 + 标签）；关于页、合集页、后台页不进索引。
- 键盘操作：↑↓ 选择、↵ 打开、ESC 关闭。

#### F7 主题切换

- 浅色（纸）/ 深色（墨）双主题；View Transitions 圆形扩散切换动画；记忆用户选择；尊重 `prefers-reduced-motion`。

#### F8 RSS `/rss.xml`

- 输出形态：**摘要模式**——每条含标题、链接、date、description；全文不进 RSS（保护站内阅读 + 引流）。
- F9 404 页面带返回首页与搜索引导。

### 3.2a 合集功能（本期新增）

#### F17 合集前台

- **数据来源：合集注册表 `src/data/collections.json`**（每条含：name 中文名 / slug ASCII / description 一句话），构建时与文章 frontmatter 的 `series` 字段合并——注册表 slug 优先，文章按 series 名归卷。**空合集（注册表中有、暂无成员文章）合法存在**，显示"待更新"状态。
- **合集列表页 `/collections/`**：全部合集以"书架"式卡片呈现——合集名、一句话描述、成员文章数、最近更新时间；空合集显示"待更新"。
- **合集详情页 `/collections/<slug>/`**：合集介绍 + 成员文章按 `seriesOrder` 排序的列表（当前阅读文章高亮，**不分页**）；每篇成员文章详情页底部附"所属合集"导航盒（本合集上一篇/下一篇/返回合集目录）。
- 合集 slug 一律 ASCII（规避中文 URL 404）；合集名页面显示可中文。
- 归集规则：文章 frontmatter 写 `series: 合集名` + `seriesOrder: 序号`，构建时自动归卷；**一篇文章只属一个合集**。

#### F18 合集后台管理（/console 内）

- 合集列表管理：创建（名称/描述/ASCII slug）、改名（自动同步改成员文章 frontmatter 与注册表）、编辑描述、删除（**仅从注册表移除，成员文章保留并解除归属**）。
- 合集元数据读写目标：`src/data/collections.json`（经 Contents API）。
- 文章编辑器 frontmatter 增加 series / seriesOrder 字段（下拉选择已有合集或新建）。
- 全部操作经 Contents API 直写仓库，commit 留痕。

#### F19 giscus 评论接入

- 评论组件置于文章详情页底部，IntersectionObserver 懒加载（滚动到才加载，保性能）。
- **评论与页面路径绑定：slug 一经发布不可变更**（改 slug 评论即失联；如必须改，需在 config 中追加旧→新路径映射或接受评论清零）。
- 前置条件（站长一次性操作，我会给逐步指引）：
  1. 仓库 Settings → General → Features 勾选 **Discussions**；
  2. 安装 giscus App：https://github.com/apps/giscus （授权给 tech_blog 仓库）；
  3. 打开 https://giscus.app/zh-CN 按提示生成 `repoId` 与 `categoryId`，发给我或自行填入 `src/config.ts`。
- 权限遵循 §2.3：评论者 GitHub 登录后方可评论；评论数据在仓库 Discussions 中，站长拥有全部管理权。
- giscus 主题跟随站点浅色/深色主题自动切换。
- 未完成上述配置前，评论区自动隐藏（config 中 `enabled: false` 兜底），不影响上线。

### 3.3 后台功能明细（/console/，唯一写入口）

#### F10 登录认证

- 页面仅一个"访问令牌"输入框。输入 PAT → 调 GitHub API `GET /user` + 仓库权限校验（验证 Token 有效且对本仓库有写权限）→ 通过后进入后台。
- Token 仅存浏览器 localStorage（不经过任何第三方服务器）；提供"退出"清除 Token。
- 连续失败 5 次提示检查 Token 权限（fine-grained / 仓库范围 / 是否过期）。
- **中途失效处理**：后台任一写操作返回 401/403 时，统一弹层提示"访问令牌已失效，请重新输入"，当前编辑内容保留不丢（见 F12 防丢机制）。
- PAT 有效期建议 90 天（到期重发，属于站长 GitHub 侧操作）。

#### F11 文章管理

- 列表：全部文章（含草稿，带"草稿/已发布"徽章），按更新时间倒序；关键字搜索、按标签筛选。
- 操作：**置顶/取消置顶**（pinned 字段切换）、**删除**（二次确认对话框）、进入编辑。
- 所有操作经 Contents API 直写仓库，自动 commit（message 规范：`post: 新建 xxx` / `post: 置顶 xxx` 等），仓库历史即操作审计日志。

#### F12 Markdown 编辑器

- 新建/编辑两模式；frontmatter 字段：title / description / date / tags / series / seriesOrder / pinned / draft / **slug（编辑器显式提供输入框）**。
- **slug 输入框**：默认按标题自动生成（中文标题→拼音或随机短码，保证 ASCII），可手动修改；发布后不可变更（F19 评论绑定约束），编辑已有文章时该框锁定并提示。
- **date 默认值**：新建时自动填当天，可改。
- **标签输入**：自由输入 + 已有标签下拉提示（输入时联想，回车成徽章），不限制新建。
- 编辑器：分栏预览（写左边看右边）、常用工具栏（标题/加粗/引用/代码块/表格/链接/**图片/附件**）。
- **图片/附件按钮**：点击即触发与拖拽/粘贴相同的上传流程（F13），成功后在光标处插入引用。
- **防丢机制**：编辑内容（含 frontmatter）每 30 秒自动暂存至 localStorage；保存失败/浏览器意外关闭后重新进入可恢复未保存内容；成功保存后清除暂存。
- 保存 = 经 Contents API 写入 `src/content/posts/<slug>.md`；草稿（draft: true）构建时不渲染上线。
- 保存成功提示"已提交，1~2 分钟后线上生效"。

#### F13 图片/附件上传

- 拖拽 / 粘贴 / 点击选择（工具栏按钮）；经 Contents API base64 上传至 `public/uploads/<yyyy>/`。
- **同名冲突**：自动追加短时间戳后缀（`xxx-a1b2.png`），不覆盖已有文件。
- 图片插入：`![描述](/uploads/2026/xxx.png)`；**非图片附件插入：`[文件名](/uploads/2026/xxx.pdf)` 链接形式**。
- 前端压缩：>500KB 图片自动 canvas 压缩后上传（有损，站长已确认）。
- **上传上限：单文件 ≤ 40MB**（站长确认执行；浏览器 base64 编码会放大约 1.33 倍，GitHub Contents API 对接近上限文件可能较慢，实现时超时给明确报错提示而非静默失败）。

### 3.4 数据层

#### F14 文章数据（"云端数据库"）

- 位置：`src/content/posts/*.md`；Astro content collections + zod 校验（字段非法则构建报错，防脏数据上线）。
- schema：title(必填) / description(必填) / date(必填) / tags(数组，默认[]) / series(可选) / seriesOrder(可选，数字) / pinned(bool) / draft(bool)。
- **合集元数据注册表**：`src/data/collections.json`（见 F17），与文章数据分离。

#### F15 附件存储（"云存储"）

- 位置：`public/uploads/`；引用路径 `/uploads/<yyyy>/<file>`；随仓库版本化，天然备份。

### 3.5 工程与部署

#### F16 CI/CD

- `deploy.yml`：push main 触发 + `schedule: cron '30 6 * * *'`（北京时间每日 14:30 定时重建，兜底）。
- 流程：npm ci → astro build → pagefind 索引 → deploy-pages。
- Pages Source 模式选 **GitHub Actions**（规避内置 Jekyll 构建冲突）。
- 构建安全：Pages 仅发布静态产物；后台 console 页随站发布但功能受 PAT 门禁（见 §2.2）。
