# LZW 的个人主页 · 开发方案与技术路径

> 参考模板：https://gsh150801.github.io/tech-blog/（拾集 · SH·JOURNAL）
> 原则：模板的视觉与交互优先级高于文字描述；全链路零成本；单人维护。
> 版本：v1.0（2026-09-29）

---

## 一、需求清单与结论速览

| # | 需求 | 结论 | 实现载体 |
|---|------|------|----------|
| 1 | 文章列表 | ✅ | Astro 构建时从仓库 `content/posts/*.md` 生成 |
| 2 | 文章详情 | ✅ | 路由式静态页 + Shiki 代码高亮 + TOC 目录 |
| 3 | 标签分类筛选 | ✅ | 构建时枚举标签 → `/tags/` 标签云 + `/tags/[tag]/` 单标签列表 |
| 4 | 关于页面 | ✅ | `/about/` 单页 |
| 5 | Markdown 渲染 | ✅ | Astro 原生内容集合（GFM：表格/任务列表/脚注/折叠块） |
| 6 | 文章数据存云端数据库 | ⚠️ 方案转换 | GitHub 仓库 = 免费云端数据源（结构化 + 版本化 + 免费） |
| 7 | 图片与附件云存储 | ⚠️ 方案转换 | GitHub 仓库 `public/uploads/`（主）+ Issues 附件（备选） |
| 8 | 零成本 + GitHub 托管 | ✅ | GitHub Pages，完全匹配参考模板架构 |
| 9 | 登录认证 | ✅ 分层 | 评论认证用 giscus（GitHub OAuth）；后台认证用 GitHub PAT（细粒度令牌） |
| 10 | 线上部署 | ✅ | GitHub Actions：push 触发 + 每日定时重建 |

**关键认知**：参考模板的架构（Astro + GitHub Pages）本身就建立在"仓库即数据库、仓库即对象存储"之上。它通过一个内置于站点的 `/console` 写作后台，用 GitHub Contents API 实现在线写文章、传图、管理合集——这正是"云端数据库 + 云端存储 + 登录认证"三个需求在零成本约束下的最优解。

## 二、总体架构

```
访客浏览器
   │  无需登录，直接访问
   ▼
GitHub Pages（静态托管）
   ▲ 构建产物
   │
Astro 5 静态生成 ──构建时读取──▶ GitHub 仓库数据层
   │                              ├─ content/posts/*.md   （文章数据）
   │                              ├─ public/uploads/*     （图片/附件）
   │                              └─ src/config.ts        （站点配置）
   │
   ├─ 定时任务：GitHub Actions schedule（每日重建，抓取新增内容）
   ├─ 写作后台 /console：浏览器内编辑 → GitHub Contents API 直写仓库
   ├─ 登录认证：GitHub PAT（后台）/ GitHub OAuth（giscus 评论）
   └─ Pagefind：构建后生成全文搜索索引（支持中文）
```

数据流向分两条：
- **读路径（访客）**：请求 → Pages 静态 HTML → 秒开，零服务器。
- **写路径（站长）**：登录后台 → GitHub API 写入 md 文件 → push 触发 Actions → 约 1 分钟后站点自动更新。

## 三、技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 框架 | **Astro 5 + TypeScript** | 与参考模板同栈；默认零 JS、性能极佳；内容集合 + zod 校验 frontmatter |
| 样式 | 手写 CSS（纸墨双主题 CSS 变量） | 还原模板视觉；无运行时开销 |
| Markdown | Astro 内容集合 + GFM + Shiki（构建时双主题高亮） | 与模板一致 |
| 搜索 | Pagefind（构建后索引、懒加载、支持中文分词） | 与模板一致；无需服务端 |
| 主题切换 | View Transitions 圆形扩散动画 | 模板招牌交互 |
| 评论 | giscus（GitHub Discussions 驱动，评论者需 GitHub 登录） | 零成本评论 + 天然登录认证 |
| 托管 | GitHub Pages | 免费公网托管 |
| CI/CD | GitHub Actions（deploy.yml：push 触发 + cron 每日 06:30 UTC 定时重建） | 自动部署 + 定时任务兜底 |
| 图片/附件 | 仓库内 `public/uploads/`（在线后台上传走 Contents API） | 单仓库闭环，运维最简 |

**被否决的备选**：
- Cloudflare Pages/Workers + D1 + R2：功能更强（真·动态 API），但需注册第三方账号 + 绑卡验证 + 多系统运维，对单人博客属过度设计；
- Supabase / Turso 等"免费云数据库"：同样引入账号与额度管理负担，且静态站前端直连数据库有安全设计成本；
- 纯本地 md 手写 + git push（不带后台）：最简单，但不满足"云端在线管理"体验。

## 四、功能模块实现方式

### 4.1 视觉与交互还原（对标模板）

- **顶栏**：左侧印章式 Logo（`LZW`朱砂印章风格）+ 站名「LZW · 个人主页」；导航：首页 / 文章 / 标签 / 关于；右侧 ⌘K 搜索 + 主题切换。
- **首页**：Hero 大标题 + 标语（中文字间距拉开，呼应"拾技术之美"的排版气质）→ 统计数字块（文章数/标签数）→ 置顶精选文章大卡 → 最新落笔列表 → 页脚（导航重复 + RSS + 版权 + "用 Astro 构建"）。
- **文章条目**：分离式日期块（日/年/月三段式）+ 标题 + 标签徽章 + 阅读时长 + 一句话摘要。
- **配色**：纸墨双主题。浅色 = 米白纸面底 + 墨色文字 + 朱砂强调色；深色 = 墨底 + 浅字。遵循模板"无暗色切换按钮缺失"的既有状态则补齐切换（模板本身有 ThemeToggle 组件，做圆形扩散动画）。
- **细节**：跳到正文锚点、键盘可达（ESC/↑↓/↵ 搜索操作）、尊重 `prefers-reduced-motion`、CSS 内联构建、字体只托管拉丁子集（中文走系统字体栈）。

### 4.2 页面与路由

| 路由 | 内容 |
|------|------|
| `/` | 首页（Hero + 统计 + 置顶 + 最新文章） |
| `/posts/` | 全部文章列表（按时间倒序） |
| `/posts/<slug>/` | 文章详情（正文 + TOC 滚动高亮 + 标签 + 上下篇 + giscus 评论） |
| `/tags/` | 标签云（每标签显示文章数） |
| `/tags/<tag>/` | 单标签文章列表 —— **即"标签分类筛选"** |
| `/about/` | 关于页 |
| `/console/` | 写作后台（不进 sitemap，路径不可枚举） |
| `/404` | 404 页 |
| `/rss.xml` | RSS 订阅 |

### 4.3 文章数据层（"云端数据库"）

- 存储：仓库 `src/content/posts/*.md`，frontmatter schema 用 zod 校验：

```yaml
---
title: 文章标题
description: 一句话摘要（用于列表/搜索/分享卡片）
date: 2026-09-29
tags: [标签A, 标签B]
pinned: false
draft: false
---
正文 Markdown……
```

- "数据库"属性：GitHub 仓库天然提供**结构化存储（zod schema 约束）、版本历史（commit）、回滚（revert）、异地备份（GitHub 云端）**，且写作后台提供增删改查接口——完全覆盖个人博客对数据库的全部实际需求。
- 标签筛选：构建时归集所有文章标签 → 生成标签云与单标签页；模板经验：GitHub Pages 对中文 URL 路径会 404，**标签与 slug 一律转 ASCII slug**（pinyin/hash 处理）。

### 4.4 图片与附件（"云存储"）

- 目录：`public/uploads/<yyyy>/<file>`，文章内用 `/uploads/2026/xxx.png` 引用。
- 在线后台上传：走 GitHub Contents API（base64 PUT），支持拖拽/粘贴上传，插入时自动生成 Markdown 引用。
- 容量评估：GitHub 仓库建议 < 1GB（软限制），单文件 < 100MB。个人博客文字为主、图片压缩后上传，3~5 年内无压力。
- 备选（若日后图片量大）：改投 GitHub Issues 附件（走 issue-attachments CDN）或迁移 Cloudflare Images，接口收敛在后台上传函数内，切换成本可控。

### 4.5 登录认证（分层设计）

| 场景 | 方案 | 认证方式 |
|------|------|----------|
| 评论互动 | giscus | GitHub OAuth（访客用 GitHub 账号登录后评论） |
| 写作后台 /console | GitHub PAT（细粒度 Personal Access Token，仅授权本仓库 Contents 读写） | 后台输入 Token → 前端调 Contents API → 验证通过方可写；Token 仅存浏览器 localStorage，不经过任何第三方服务器 |

安全要点（沿用模板 README 的教训）：
- Token 用**细粒度令牌**，scope 仅限博客仓库的 Contents: Read and write，设置过期时间；
- 绝不提交 Token 到仓库/文档/截图；
- `/console/` 不进 sitemap、robots.txt 屏蔽，加简单路径混淆（如 `/console-<自定义后缀>/`）。

### 4.6 搜索与评论

- **Pagefind**：`astro build` 后跑 `pagefind` 生成索引，前端 ⌘K 模态框懒加载，支持 ↑↓/↵/ESC 键盘操作，支持中文。
- **giscus**：需要仓库开启 Discussions + 安装 giscus App + 在 giscus.app 生成 repoId/categoryId 填入 `src/config.ts`（实施时需要志伟用 GitHub 账号点几下，5 分钟）。

### 4.7 写作后台（超越模板描述的增值模块）

模板仓库已内置 `/console` 能力，我们复刻同等功能：
- 文章列表管理（搜索/筛选/草稿标记/置顶管理）
- Markdown 在线编辑器（所见即所得 + 工具栏）
- 图片/附件拖拽上传并插入
- 发布 ↔ 草稿切换、删除（二次确认）
- 全部操作直写 GitHub 仓库，commit 留痕可回滚

## 六、部署与 CI/CD

`deploy.yml` 两个触发器：
1. `push` 到 main → 构建部署（在线后台发文后 ~1 分钟生效）；
2. `schedule: cron '30 6 * * *'`（北京时间每日 14:30）→ 定时重建，兜底所有非 push 场景。

构建流程：`npm ci` → `astro build` → `pagefind --site dist` → `actions/deploy-pages`。
Pages 设置：Source 选 **GitHub Actions**（避免与内置 Jekyll 构建冲突——模板踩过的坑直接绕开）。
线上地址：`https://<username>.github.io/<repo>/`；日后可绑自定义域名。

## 十、风险与边界

- **直连问题**：`github.io` 国内访问偶有波动（非被墙，属线路抖动），个人博客可接受；追求稳定可日后加 Cloudflare CDN（仍免费）。
- **构建配额**：GitHub Actions 免费额度公共仓库无限、私有仓库 2000 分钟/月——公共仓库策略下零压力；若建私有仓库，每日定时任务 + 推送触发也远在额度内。
- **中文路径 404**：GitHub Pages 已知坑，slug 与标签 URL 全部 ASCII 化（已在方案内规避）。
- **Token 安全**：已在 4.5 节明确规范；如 Token 曾泄露，立即在 GitHub Settings → Tokens 撤销重发。
