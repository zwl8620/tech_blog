## 为什么要有这个博客

工作几年，笔记散落在飞书文档、本地 Markdown、聊天记录收藏里——想找的时候找不到，想分享的时候没有出口。更关键的是，很多思考停留在"做过"而没到"想清楚"。

写作是最好的复盘，这句话我深信不疑。所以我给自己搭了这个地方：**把自己学习和工作中值得沉淀的东西写出来**——生信分析的笔记、IVD 研发一线的观察、AI 时代的小小自我思考。

## 技术选型：零成本是硬约束

个人博客不赚钱，所以我的预算是 **0 元**。这个约束反而让选型变得简单：

| 需求 | 方案 | 成本 |
|------|------|------|
| 托管 | GitHub Pages | ¥0 |
| 框架 | Astro 5（静态生成） | 开源免费 |
| 数据库 | GitHub 仓库本身（文章 = Markdown 文件） | ¥0 |
| 图床 | 仓库 `public/uploads/` 目录 | ¥0 |
| 搜索 | Pagefind（构建时索引） | ¥0 |
| 评论 | giscus（GitHub Discussions） | ¥0 |
| 部署 | GitHub Actions 自动构建 | ¥0 |

为什么选 Astro 而不是 Hugo / Hexo / Next.js？

- **Astro 默认输出零 JavaScript 的静态 HTML**，页面秒开，性能预算轻松过 90 分；
- 内容集合（Content Collections）自带 zod 校验，frontmatter 写错字段构建直接报错，防脏数据上线；
- 我需要一点客户端交互（搜索、主题切换、后台），Astro 的"岛屿架构"允许按需注水，不会把整页变成 SPA。

被否决的方案也值得一提：Cloudflare Pages + D1 + R2 功能更强，但要注册第三方账号、绑卡验证，对单人博客属于过度设计；Hexo 主题生态老牌但定制成本高。**技术栈越简单，越可能维护十年**。

## 架构：仓库即数据库

这是整个设计里我最满意的部分。传统思路是找个免费云数据库存文章，但静态博客的数据特点决定了——**文章天然适合用文件表达**：

```
src/content/posts/*.md     ← 文章（云端数据库）
public/uploads/<yyyy>/*    ← 图片与附件（云存储）
src/data/collections.json  ← 合集注册表
```

好处立竿见影：

1. **版本历史即数据备份**——每一篇文章的每次修改都有 commit 记录，可 diff 可回滚；
2. **写作后台通过 GitHub Contents API 直接读写仓库**——不需要自己写服务端；
3. **clone 仓库 = 全量备份**——数据在 GitHub 手里，也在我手里。

## 权限设计：个人博客，不是博客园

这是我给自己定的铁律：**其他人只能阅读和评论，不能修改、置顶或归类我发布的文章**。

静态站的天然优势是访客侧"无接口可攻击"——所有页面都是预渲染 HTML，没有任何写操作代码。唯一的写入口是隐藏路径的写作后台，它被四层防线保护：

1. **隐藏路径**：后台地址不在任何页面出现，不进 sitemap，robots.txt 也不声明（robots 是公开文件，写 Disallow 等于广播位置）；
2. **PAT 门禁**：后台需要 GitHub 细粒度令牌（Fine-grained Token），授权范围限定本仓库 + Contents 读写权限，90 天有效期。没有令牌，GitHub API 直接 401；
3. **令牌不落地**：Token 只存浏览器 localStorage，不经过任何第三方服务器；
4. **仓库保护**：仓库在我个人账号下，开启 2FA。

评论区用 giscus：评论者需要 GitHub 登录，评论数据存在仓库 Discussions 里，我只拥有管理权，评论者碰不到文章内容——权限模型天然自洽。

## 写作后台

既然仓库是数据库，"在线写作"就变成了一个纯前端问题：调 GitHub Contents API 写文件。后台实现了：

- 文章列表管理（搜索、置顶、删除、草稿标记）
- Markdown 编辑器（分栏预览、常用工具栏）
- 图片/附件上传（>500KB 自动压缩，同名自动加时间戳，单文件 ≤ 40MB）
- 合集管理（改合集名会自动同步所有成员文章的 frontmatter）

细节上有两个值得记录的决策：

- **slug 发布后锁定**：giscus 评论按页面路径绑定，改 slug 意味着评论失联。所以编辑已有文章时 slug 输入框直接禁用；
- **30 秒自动暂存**：编辑内容每 30 秒写入 localStorage，断网、误关标签页都不丢稿。

## 踩过的坑

- **GitHub Pages 中文 URL 会 404**：中文标签、合集名如果直接出现在 URL 路径里，即便文件存在也 404。解决：所有 slug 一律 ASCII 化（拼音/短码映射）；
- **Pages 的 Source 必须选 "GitHub Actions"**：默认的 legacy 模式会用内置 Jekyll 构建，和自定义 workflow 打架；
- **base 路径**：仓库部署的站点挂在 `/tech_blog/` 子路径下，所有内部链接、favicon、RSS 引用都要带前缀，Astro 的 `base` 配置只能解决一半，组件里的硬编码链接要自己盯住。
